# @cloud/i18n 设计 — 多语言 / 数字 / 日期时间

> 状态：spec(draft)
> 日期：2026-05-17
> 范围：基建包 `@cloud/i18n` + admin app 接入；partner / merchant 后续按文档复制

---

## 1. 背景与目标

当前 monorepo 三个 Next.js app（admin / partner / merchant）UI 文案全部硬编码中文，`<html lang="zh-CN">`，无任何 i18n 基建。需要：

- 支持 **en（默认 / fallback）+ zh-CN + ja** 三语
- 文案、数字、日期/时间统一走同一套 API
- locale 切换不改 URL，cookie 记忆
- 时区随浏览器本地（且 SSR 不出 hydration mismatch）
- 基建以 workspace 包形态共享，单 app 接入成本低

本期产出基建包 + admin 接入；partner / merchant 复制路径，文档化，不在本期开发范围。

## 2. 决策汇总

| 维度 | 决策 | 备选 / 理由 |
|---|---|---|
| 语言库 | `next-intl` | RSC + Server Action 原生支持；cookie-only 路由官方有 pattern；`useFormatter` 一处搞定数字/日期/相对时间 |
| 语言集合 | `en`, `zh-CN`, `ja` | en 是 default & fallback |
| 路由策略 | 不带 locale prefix，全局 in-place 切换 | enterprise console，无 SEO 需求；省去 `app/[locale]/` 改造 |
| locale 来源 | cookie `locale`；缺失则 `en` | 不读 `Accept-Language`：避免首访体验抖动 |
| locale 切换 | UI 触发 Server Action 写 cookie，再 `router.refresh()` | server-action 与 `@cloud/auth` 的 cookie 写入风格一致 |
| 时区策略 | cookie `tz`（IANA 名）；server fallback `UTC`；client 首访自动探测并写回 | 解决 SSR 不知道浏览器 TZ 的问题，代价是首访可能 refresh 一次 |
| 数字 / 货币 | `Intl.NumberFormat`（通过 next-intl `useFormatter` / `getFormatter`）；币种与 locale 解耦 | 业务数据是 CNY 就显示 ¥，不随 ja 变 ¥日元 |
| 消息文件 | `apps/<app>/messages/{en,zh-CN,ja}.json` + `packages/ui/messages/{en,zh-CN,ja}.json`，运行时 deep-merge | 业务文案归 app，UI 组件文案归 ui 包 |
| Namespace | 顶层 key 分业务域（`common` / `auth` / `users` / `ui` 等） | 单文件不过载，多人改不冲突 |
| 类型安全 | `en.json` 为权威 schema；`packages/i18n/src/messages.d.ts` 声明 `IntlMessages` 接口 | next-intl 用它推断 `t()` key 自动补全 |
| Fallback | 缺 key → en；en 也缺 → dev `throw`，prod 回 key 字符串 | 开发期暴露问题，生产期不整页崩 |

## 3. 包结构

新增 workspace 包 `@cloud/i18n`：

```
packages/i18n/
├── package.json
├── tsconfig.json
└── src/
    ├── index.ts          # 共用常量/类型: locales, defaultLocale, Locale
    ├── cookie.ts         # LOCALE_COOKIE / TZ_COOKIE 常量，cookie 读取工具（中立）
    ├── formats.ts        # 数字/日期格式预设（中立）
    ├── messages.d.ts     # IntlMessages 接口（next-intl 类型推断锚点）
    ├── server.ts         # 首行 "server-only"; createI18nRequestConfig + setLocaleAction + setTimeZoneAction
    └── client.ts         # 首行 "use client"; <LocaleSwitcher>, <TimeZoneInit> 及 hooks 透传
```

`package.json` exports：

```jsonc
{
  "exports": {
    ".":        "./src/index.ts",
    "./server": "./src/server.ts",
    "./client": "./src/client.ts"
  }
}
```

`server.ts` 顶部 `import "server-only"` —— 防止 client component 直接或间接 import 后把 `cookies()` / Server Action 私有逻辑带进 client bundle。

> 命名规约：用文件名而非文件夹区分 server/client，与 `@cloud/security` 一致。

## 5. Cookie 设计

常量 `COOKIE_MAX_AGE_SECONDS = 365 * 24 * 60 * 60`（1 年）。

| Cookie | 值 | 写入者 | maxAge | 备注 |
|---|---|---|---|---|
| `locale` | `en` / `zh-CN` / `ja` | `setLocaleAction` (Server Action) | `COOKIE_MAX_AGE_SECONDS` | path=/，sameSite=lax，httpOnly=false（无敏感语义，可省一次往返） |
| `tz` | IANA 时区名，如 `Asia/Shanghai` | `setTimeZoneAction` (Server Action) | `COOKIE_MAX_AGE_SECONDS` | 同上 |

两个 cookie 都不是敏感数据，httpOnly=false 让 `<TimeZoneInit>` 客户端组件可以读后再决定是否调 action（避免每次首访都跑 action）。

`cookie.ts` 暴露：

```ts
export const LOCALE_COOKIE = "locale";
export const TZ_COOKIE = "tz";
export function readLocaleCookie(cookies: ReadonlyCookies): Locale | null;
export function readTimeZoneCookie(cookies: ReadonlyCookies): string | null;
```

## 6. Server 集成

### 6.1 共享配置工厂（在 `@cloud/i18n/server`）

```ts
export function createI18nRequestConfig(opts: {
  loadMessages: (locale: Locale) => Promise<IntlMessages>;
}) {
  return getRequestConfig(async () => {
    const cookieStore = await cookies();
    const locale = readLocaleCookie(cookieStore) ?? defaultLocale;
    const timeZone = readTimeZoneCookie(cookieStore) ?? "UTC";
    // 关键：把 en 当兜底层，深合并到当前 locale，保证 zh/ja 缺 key 时静默回 en 文案
    const enMessages = await opts.loadMessages("en");
    const currentMessages = locale === "en" ? enMessages : await opts.loadMessages(locale);
    const messages = deepMerge(enMessages, currentMessages);
    return {
      locale,
      timeZone,
      messages,
      formats: { number: numberFormats, dateTime: dateTimeFormats },
      onError: createErrorHandler(),
      getMessageFallback: createFallback(),
    };
  });
}
```

兜底两级：
1. **跨 locale fallback**：`deepMerge(enMessages, currentMessages)` 在 `getRequestConfig` 阶段就把 en 当作 base 层 —— 这是 next-intl 的推荐做法，因为它不内置 "missing key → 切到别的 locale 找" 的运行时行为。
2. **en 也缺 key**：`createFallback` 在 dev 抛错暴露漏抽，prod 返回 `namespace.key` 字符串防整页崩。

`deepMerge` 实现：本包内手写一个 ~10 行 TS 工具（仅处理 plain object，不处理数组合并 / Date / Map），不引第三方依赖。位置 `packages/i18n/src/deep-merge.ts`，单测覆盖。

### 6.2 每 app 的薄包装（admin 示例）

`apps/admin/i18n/request.ts`：

```ts
import { createI18nRequestConfig, deepMerge } from "@cloud/i18n/server";
import type { Locale } from "@cloud/i18n";

const loadMessages = async (locale: Locale) => {
  const [appMsgs, uiMsgs] = await Promise.all([
    import(`../messages/${locale}.json`).then(m => m.default),
    import(`@cloud/ui/messages/${locale}.json`).then(m => m.default),
  ]);
  return deepMerge(uiMsgs, appMsgs); // 同 key 时 app 覆盖 ui
};

export default createI18nRequestConfig({ loadMessages });
```

> `deepMerge` 从 `@cloud/i18n/server` re-export（实现位于 `src/deep-merge.ts`），所有 app 共用同一个实现，避免每 app 重复造。

`apps/admin/next.config.ts` 顶部包一层：

```ts
import createNextIntlPlugin from "next-intl/plugin";
const withNextIntl = createNextIntlPlugin("./i18n/request.ts");
export default withNextIntl(nextConfig);
```

### 6.3 Server Actions（`@cloud/i18n/server`）

```ts
"use server";
export async function setLocaleAction(locale: Locale) {
  (await cookies()).set(LOCALE_COOKIE, locale, { path: "/", maxAge: ONE_YEAR, sameSite: "lax" });
}
export async function setTimeZoneAction(tz: string) {
  if (!isValidIanaTimeZone(tz)) return;
  (await cookies()).set(TZ_COOKIE, tz, { path: "/", maxAge: ONE_YEAR, sameSite: "lax" });
}
```

`isValidIanaTimeZone` 用 `Intl.supportedValuesOf("timeZone").includes(tz)` 校验，防伪造写入。

## 7. Client 集成

### 7.1 Provider

`apps/admin/app/layout.tsx` 顶部接入：

```tsx
import { NextIntlClientProvider } from "next-intl";
import { getLocale, getMessages, getTimeZone } from "next-intl/server";

export default async function RootLayout({ children }) {
  const [locale, messages, timeZone] = await Promise.all([
    getLocale(), getMessages(), getTimeZone(),
  ]);
  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider locale={locale} messages={messages} timeZone={timeZone}>
          <TimeZoneInit />
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

`<html lang>` 跟 `locale` 自动同步，移除 hardcoded `zh-CN`。

### 7.2 `<TimeZoneInit />`（`@cloud/i18n/client`）

```tsx
"use client";
export function TimeZoneInit() {
  const currentTz = useTimeZone();
  useEffect(() => {
    const detected = Intl.DateTimeFormat().resolvedOptions().timeZone;
    if (detected && detected !== currentTz) {
      startTransition(async () => {
        await setTimeZoneAction(detected);
        router.refresh();
      });
    }
  }, [currentTz]);
  return null;
}
```

首访时间线：

1. 用户首次进入 → 无 `tz` cookie → server 用 UTC 渲染
2. 客户端 hydrate → `<TimeZoneInit>` 检测真实 TZ ≠ UTC → 调 action 写 cookie
3. `router.refresh()` 触发 RSC 重新渲染（这次用正确 TZ）
4. 后续所有请求都直接读 cookie，无 refresh

代价：首访多一次 RSC 渲染。可接受。

### 7.3 `<LocaleSwitcher />`（`@cloud/i18n/client`）

```tsx
"use client";
export function LocaleSwitcher() {
  const locale = useLocale();
  const router = useRouter();
  return (
    <select value={locale} onChange={(e) => {
      startTransition(async () => {
        await setLocaleAction(e.target.value as Locale);
        router.refresh();
      });
    }}>
      {locales.map(l => <option key={l} value={l}>{localeLabels[l]}</option>)}
    </select>
  );
}
```

注入位置：`AppShell` 的 `headerActions` 区。

## 8. 格式预设

`packages/i18n/src/formats.ts`：

```ts
export const numberFormats = {
  decimal: { maximumFractionDigits: 2 },
  integer: { maximumFractionDigits: 0 },
  percent: { style: "percent", maximumFractionDigits: 1 },
  CNY: { style: "currency", currency: "CNY" },
  USD: { style: "currency", currency: "USD" },
  JPY: { style: "currency", currency: "JPY", maximumFractionDigits: 0 },
} satisfies Record<string, Intl.NumberFormatOptions>;

export const dateTimeFormats = {
  short:    { year: "numeric", month: "2-digit", day: "2-digit" },
  long:     { year: "numeric", month: "long", day: "numeric", weekday: "short" },
  time:     { hour: "2-digit", minute: "2-digit" },
  dateTime: { year: "numeric", month: "2-digit", day: "2-digit", hour: "2-digit", minute: "2-digit" },
} satisfies Record<string, Intl.DateTimeFormatOptions>;
```

币种 enum 后续随业务扩展（如新增日元业务再加 `JPY` 调用方）。币种参数由调用方显式传，不耦合 locale。

## 10. 类型安全

`packages/i18n/src/messages.d.ts`：

```ts
import type enMessages from "../../../apps/admin/messages/en.json"; // 锚定 admin 的 en 为权威
import type uiMessages from "../../ui/messages/en.json";

type MergedMessages = typeof uiMessages & typeof enMessages;

declare global {
  interface IntlMessages extends MergedMessages {}
}
```

> 注：用相对路径导入 admin 的 messages 是为本期单 app 简化。partner / merchant 接入时改造为按 app 切换的 `tsconfig paths` 或干脆每个 app 自带一份 `messages.d.ts`。spec 末尾给迁移建议。

CI 脚本 `pnpm i18n:check`：

- 以 admin 的 `en.json` 为 source of truth
- zh-CN / ja 缺 key → warn（允许翻译滞后）
- zh-CN / ja 多 key（孤儿 key）→ error
- ui 包同此处理

## 11. Fallback

两级 fallback 已在 §6.1 内联说明：

1. **第一级（跨 locale）**：`createI18nRequestConfig` 在 `getRequestConfig` 阶段 `deepMerge(enMessages, currentLocaleMessages)`。zh / ja 缺 key 时静默回 en 文案，不触发任何 error 路径。
2. **第二级（en 也缺）**：next-intl 调 `getMessageFallback`：

```ts
function createFallback() {
  return ({ namespace, key, error }: { namespace?: string; key: string; error: IntlError }) => {
    if (error.code === IntlErrorCode.MISSING_MESSAGE) {
      if (process.env.NODE_ENV !== "production") throw error;
      return namespace ? `${namespace}.${key}` : key;
    }
    return key;
  };
}
```

`onError` 同步上报一次（dev 环境 `console.error`），避免无声漏抽。

## 14. 排障

| 现象 | 检查 |
|---|---|
| `<html lang>` 与文案不一致 | RootLayout 是否用 `await getLocale()`；`locale` cookie 是否写入 |
| Server `getFormatter` 报错 `timeZone is not defined` | `getRequestConfig` 是否返回 `timeZone`；首访前 `tz` cookie 未写时 server 应回 `UTC` |
| 切换语言后 client 看到旧文案 | switcher 是否调用 `router.refresh()`；`NextIntlClientProvider` 是否接受了新 messages |
| Hydration mismatch on date | 业务代码是否绕过 `useFormatter` 直接用 `Date.prototype.toLocaleString()` |
| `useTranslations` 类型推断没自动补全 | `messages.d.ts` 是否被 tsconfig 收纳；`IntlMessages` 全局接口是否声明 |

## 16. 不在本期范围

- 服务端日志、Server Action 错误的 i18n（暂用 en）
- email / SMS / 推送的 i18n
- 数据库内容（用户名、商品名）的多语言存储
- 阅读方向（RTL）

- 翻译 SaaS（Crowdin / Lokalise）集成
- 翻译滞后的可视化报表
