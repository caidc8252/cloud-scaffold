# Carbon · 客户管理后台 — 公共约束（对外交接版）

> 范围：客户（Customer）、合同（Contract）、操作员（Operator）、角色与权限（Role / Permission）、订单（Order）、设备（Device）、审计事件（Event / Audit）、通知（Notification）。
> 受众：与本项目对接的其它系统（例如：通知中心、客户自助门户、设备激活服务、订单/履约系统、计费/发票系统、IAM）。

---

## 1. 数据字典

### 1.1 客户公司 Customer
| 字段 | 类型 | 必填 | 取值 / 说明 |
|---|---|---|---|
| `id` | string (`c-xxx`) | ✓ | 业务主键 |
| `name` | string | ✓ | 公司名 |
| `address` | string | – | 一行制完整地址 |
| `license` | string | – | 营业执照/许可证号，可为空 |
| `notes` | string | – | 内部备注 |
| `status` | enum | ✓ | `Active` / `Onboarding` / `Suspended` |
| `registeredAt` | ISO8601 | ✓ | 后台注册时间 |
| `contracts` | Contract[] | ✓ | 见 1.2 |
| `operators` | Operator[] | ✓ | 见 1.3 |
| `events` | Event[] | ✓ | 审计事件流，见 1.7 |

### 1.2 合同 Contract
| 字段 | 类型 | 取值 / 说明 |
|---|---|---|
| `kind` | enum | `ISV` / `ISO` / `Acquirer` / `PayFac`（四种合同类型，可叠加） |
| `status` | enum | `Active` / `Signed` / `Pending` / `Terminated` |
| `signedAt` | ISO8601 | 配置/签署时间 |
| `signedBy` | email | 配置人或客户管理员邮箱 |
| _派生 ID_ | `CT-{KIND}-{customerId 后4位}` | UI 展示用，非存储字段 |

合同的语义说明：
- `ISV` Independent Software Vendor
- `ISO` Independent Sales Organization
- `Acquirer` 收单机构
- `PayFac` Payment Facilitator

### 1.3 操作员 Operator
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | – | 邀请未接受时为空 |
| `email` | email | ✓ | 登录身份 |
| `phone` | E.164 | – | 国际号码 |
| `role` | string | ✓ | 引用 Role.name（见 1.4），系统默认含 `Admin` / `Operator` / `Viewer` |
| `lastLogin` | ISO8601 \| null | – | 未登录为 null |
| `pending` | bool | – | true 表示邀请未接受 |
| `locked` | bool | – | true 表示账户被锁定 |

### 1.4 角色 Role
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `r-xxx` | 主键 |
| `name` | string | 角色名（**所有客户共用同一套角色**） |
| `description` | string | 描述 |
| `builtin` | bool | 系统内置角色不可改名/删除 |
| `operatorCount` | int | 引用此角色的操作员数（派生统计） |
| `permissions` | string[] | 权限 ID 数组，见 1.5 |
| `contractMode` | enum | `allow` / `deny`（白名单 / 黑名单） |
| `contractsAllowed` | enum[] | `ISV` / `ISO` / `Acquirer` / `PayFac` 的子集 |
| `updatedAt` | ISO8601 | – |
| `updatedBy` | email | – |

### 1.5 权限 Permission（系统预置，不可新增）
权限 ID 命名空间：

| 命名空间 | 权限 ID |
|---|---|
| 客户管理 `cust.*` | `cust.view`、`cust.edit`、`cust.create`、`cust.suspend`、`cust.delete` |
| 合同 `ctr.*` | `ctr.view`、`ctr.add`、`ctr.sign`、`ctr.terminate`（均受合同类型作用域控制） |
| 操作员 `op.*` | `op.view`、`op.invite`、`op.role`、`op.lock`、`op.mfa`、`op.remove` |
| 敏感数据 `data.*` / `audit.*` | `data.reveal`、`data.export`、`audit.view` |
| 系统 `sys.*` | `sys.roles`、`sys.templates`、`sys.notify`、`sys.keys` |

> 标注 `contracts: ['ISV','ISO','Acquirer','PayFac']` 的权限受合同类型作用域控制，**实际生效 = 权限 ∧ 角色合同作用域**。

### 1.6 订单 Order / 行项 OrderItem / 设备 Device
**Order**
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `o-YYYY-NNNN` | 内部 ID |
| `number` | `SO-YYYY-NNNN` | 对外单号 |
| `customerId` / `customerName` | – | 反向引用 Customer |
| `createdAt` / `createdBy` | – | – |
| `status` | enum | `Awaiting payment` / `Awaiting shipment` / `Shipped` / `Partially complete` / `Complete` / `Cancelled` |
| `items` | OrderItem[] | – |
| `discountPct` | int 0–100 | 整单折扣 |
| `notes` | string | – |
| `shipping` | `{ name, address, method, tracking? }` | 收货信息 |
| `events` | Event[] | 订单事件流 |

**OrderItem**
| 字段 | 说明 |
|---|---|
| `modelId` / `modelName` / `unitPrice` | 引用 DeviceModel（1.6.1） |
| `qty` | 数量 |
| `type` | `Semi-integration` / `Stand-alone` |
| `devices` | Device[]，长度可 < qty（未录入），≤ qty |
| `shipped` | bool，行项级发货状态（用于部分发货） |

**Device**
| 字段 | 说明 |
|---|---|
| `sn` | 设备序列号 |
| `code` | **6 位**激活码（开机展示，逐机绑定 SN） |
| `type` | 同 OrderItem.type |

**1.6.1 DeviceModel（产品目录）**
`{ id, name, family, desc, unitPrice, types: ('Semi-integration'|'Stand-alone')[], image }`

### 1.7 审计事件 Event
通用结构：`{ at: ISO8601, kind: string, by: email|"system", text: string }`

`kind` 取值（已出现的）：
- 客户域：`created`、`contract+`、`contract✓`、`contract-`、`operator+`、`info`、`reveal`、`warn`
- 订单域：`created`、`invoice`、`paid`、`ship`、`activate`、`deliver`、`free`

## 2. 业务规则

### 2.1 客户生命周期
- 默认 `Onboarding`；至少 1 个合同 `Active` 且至少 1 个 `Admin` 操作员接受邀请后转 `Active`。
- `Suspended` 由系统管理员显式切换，会写入 `warn` 事件。
- 客户的合同可同时存在多种（ISV+ISO+…），互不互斥。

### 2.2 合同
- **合同由后台配置，不再走客户端签署流程**（settings.jsx 注释明确：`Contract Templates removed: contracts are now back-office configured per-customer`）。
- 状态机：`Pending` → `Active`/`Signed` → `Terminated`；`Terminated` 为终态。
- 终止合同 ≠ 删除合同：`Active`/`Signed` 状态下"删除"动作 = 标记为 `Terminated` 并要求填写理由（写入审计）；`Pending` 状态下才可硬删。
- 合同模板维护权限：`sys.templates`，按合同类型分桶。

### 2.3 操作员 & 角色
- **角色全局共享**（不属于某个客户），所有客户使用同一份角色定义。
- 内置角色：`Operator`、`Viewer`（`builtin: true`，不可删/不可重命名）；`Admin` 为客户首位操作员的隐式身份。
- 角色的"合同作用域"语义：
  - `contractMode = 'allow'`：仅能操作 `contractsAllowed` 列出的合同类型；
  - `contractMode = 'deny'`：默认全部允许，但若给出 `contractsAllowed` 则视为黑名单例外。
- 新操作员通过**邀请链接 / QR 码**接入；`pending = true` 直到首次激活。

### 2.4 敏感信息与脱敏
- 邮箱、电话、姓名默认按 EO 14117 / GDPR 规则脱敏显示。
- 解除脱敏（`data.reveal`）**必须写审计**：`{ kind: 'reveal', text: 'Sensitive field revealed: <field>' }`。
- 导出 CSV 受 `data.export` 控制。

### 2.5 订单状态机
```
Awaiting payment ──(paid 或 discount=100%)──▶ Awaiting shipment
                                                   │
                                                   ├─(activate 全部完成 → ship)─▶ Shipped ──▶ Complete
                                                   └─(部分发货)─▶ Partially complete ──▶ Complete
任意状态 → Cancelled
```
- `discountPct = 100` 时跳过付款，直接进入 `Awaiting shipment`，写入 `free` 事件。
- `Complete` 由 `deliver` 事件（一般来自履约系统回调）触发。

### 2.6 设备激活规则
- 每台设备**开机展示且仅展示一次** 6 位激活码，与 SN 一对一记录。
- 行项设备数组可少于 `qty`（即"待激活"占位）。
- 设备状态（派生）：
  - `Pending activation`：`sn` 或 `code` 为空，或 `code.length != 6`；
  - `Deployed`：已激活 **且** （order.status ∈ `Shipped`/`Complete` 或 item.shipped=true）；
  - 否则为 `Activated · in warehouse`（即 UI 上的非 Deployed 已激活态）。
- 行项支持部分发货（`item.shipped`），订单整体进入 `Partially complete`。

### 2.7 金额计算
- `subtotal = Σ unitPrice * qty`
- `total = round( subtotal * (1 - discountPct/100), 2 )`
- 货币：USD（前端固定 `en-US` 格式化，后端建议存最小货币单位 + ISO-4217 currency code 字段）。

## 3. 与外部系统的关系

### 3.1 通知 / 消息（**这是下游项目要重点接的部分**）

| 触发事件 | 触发方 | 建议通道 | 收件人 | 负载关键字段 |
|---|---|---|---|---|
| 客户注册完成 | 客户管理后台 | 站内信 + Email | 该客户的全部 Admin、Carbon 内部运营 | `customerId`、`name`、`registeredAt` |
| 合同新增 / 终止 | 客户管理后台 | 站内信 + Email | 客户全部 Admin | `customerId`、`contractKind`、`status`、`actor` |
| 操作员邀请 | 客户管理后台 | **Email + 邀请链接 + QR** | 被邀请邮箱 | `inviteToken`、`customerId`、`role`、`expiresAt` |
| 操作员锁定 / MFA 重置 | 客户管理后台 | Email | 被操作的操作员 + 该客户 Admin | `operatorEmail`、`action`、`actor` |
| 敏感信息被解码 (`data.reveal`) | 客户管理后台 | 站内信（仅 Compliance 角色） | 含 `data.reveal` 或 `audit.view` 的角色成员 | `customerId`、`field`、`actor`、`at` |
| 发票开具 | 计费/发票系统 | Email + 站内信 | 下单客户 Admin、`createdBy` | `orderId`、`invoiceNo`、`amount` |
| 支付到账 | 计费/支付系统（**回调**） | 站内信 | `createdBy`、Carbon 运营 | `orderId`、`paidAt`、`amount` |
| 订单发货 / 部分发货 | 履约/仓储系统（**回调**） | Email + 站内信 | 收货联系人、客户 Admin | `orderId`、`tracking`、`shippedItems` |
| 设备激活 | 设备/激活服务（**回调**） | 站内信 | `createdBy` | `orderId`、`sn`、`code`、`activatedAt` |
| 客户被 Suspended | 客户管理后台 | Email | 客户全部 Admin | `customerId`、`reason`、`actor` |

**通道配置**：本系统提供 `sys.notify` 权限，支持配置 **email / webhook 路由**，下游通知中心可通过 webhook 订阅以上事件。

### 3.2 与其它系统的接口约定（建议）
| 上游/下游 | 方向 | 接口语义 |
|---|---|---|
| **IAM / 身份服务** | ← | 操作员登录、MFA、锁账、邀请确认 |
| **计费 / 发票系统** | ↔ | 订单创建 → 发出 `invoice`；支付到账回调 → `paid` 事件 |
| **履约 / 仓储系统** | ↔ | 订单 `Awaiting shipment` 推送到仓储；仓储回写 `ship` / `deliver` / `tracking` |
| **设备激活服务** | ← | 设备首次开机上报 `(sn, code)` 对，匹配订单行项后回写 |
| **通知中心**（本次新建项目） | ← | 订阅上述事件，按收件人 + 通道分发 |
| **客户自助门户**（若存在） | ↔ | 读取脱敏后的合同、订单、设备列表；不持有 `data.reveal` 能力 |
| **审计 / SIEM** | ← | 拉取 `events`（包括 `reveal`、`warn`、`contract-`） |

### 3.3 公共契约要点
- **所有跨系统事件统一携带 `{at, kind, by, text}` 形式的审计字段**，便于下游做事件溯源。
- **邮箱/电话在跨系统传递时默认明文**，调用方必须自行实现 UI 层脱敏（参考 §2.4 规则）。
- 操作主体 `by` 取值：员工邮箱 / `admin@carbon` / `system` / `warehouse@carbon` 等内部 service account。

## 4. 建议的数据结构（对外接口形态）

### 4.1 通用约定
- 时间一律 ISO8601 + UTC（`...Z`）。
- 金额：`{ amount: integer, currency: "USD" }`（最小货币单位，分）。
- 枚举值在 wire 上一律使用 § 1 中的英文字面量（保持与代码一致）。
- 主键命名空间前缀：`c-` 客户、`o-` 订单、`m-` 设备型号、`r-` 角色、`li-` 订单行项。

### 4.2 实体 JSON 范型（TypeScript 风格）

```ts
type Email = string;        // RFC5322
type ISODateTime = string;  // 2026-05-13T08:14:00Z
type ContractKind = 'ISV' | 'ISO' | 'Acquirer' | 'PayFac';

interface Money { amount: number; currency: 'USD'; }

interface Customer {
  id: string;                // c-xxx
  name: string;
  address?: string;
  license?: string;
  notes?: string;
  status: 'Active' | 'Onboarding' | 'Suspended';
  registeredAt: ISODateTime;
  contracts: Contract[];
  operators: Operator[];     // 引用层关系也可拆为独立资源
  // events 单独走 /audit 接口，不内嵌（见 4.3）
}

interface Contract {
  kind: ContractKind;
  status: 'Active' | 'Signed' | 'Pending' | 'Terminated';
  signedAt?: ISODateTime;
  signedBy?: Email;          // 实际配置人或客户管理员
  terminatedAt?: ISODateTime;
  terminationReason?: string;
}

interface Operator {
  id: string;                // u-xxx，新增
  customerId: string;
  name?: string;
  email: Email;
  phone?: string;            // E.164
  roleId: string;            // r-xxx
  lastLoginAt?: ISODateTime;
  pending: boolean;
  locked: boolean;
  mfaEnabled: boolean;       // 新增，便于 IAM 同步
}

interface Role {
  id: string;                // r-xxx
  name: string;
  description?: string;
  builtin: boolean;
  permissions: string[];     // e.g. ['cust.view', 'ctr.add', ...]
  contractMode: 'allow' | 'deny';
  contractsAllowed: ContractKind[];
  updatedAt: ISODateTime;
  updatedBy: Email;
}

interface Order {
  id: string;                // o-YYYY-NNNN
  number: string;            // SO-YYYY-NNNN
  customerId: string;
  status:
    | 'Awaiting payment' | 'Awaiting shipment' | 'Shipped'
    | 'Partially complete' | 'Complete' | 'Cancelled';
  createdAt: ISODateTime;
  createdBy: Email;
  items: OrderItem[];
  discountPct: number;       // 0..100
  subtotal: Money;           // 派生
  total: Money;              // 派生
  notes?: string;
  shipping: {
    name: string;
    address: string;
    method: string;
    tracking?: string;
  };
}

interface OrderItem {
  id: string;                // li-x
  modelId: string;           // m-xxx
  modelName: string;
  unitPrice: Money;
  qty: number;
  type: 'Semi-integration' | 'Stand-alone';
  devices: Device[];         // length <= qty
  shipped: boolean;
}

interface Device {
  sn: string;
  code: string;              // 6 位激活码
  type: 'Semi-integration' | 'Stand-alone';
  status: 'Pending activation' | 'Activated' | 'Deployed';  // 派生
  activatedAt?: ISODateTime;
}

interface DeviceModel {
  id: string;                // m-xxx
  name: string;
  family: string;
  desc: string;
  unitPrice: Money;
  types: Array<'Semi-integration' | 'Stand-alone'>;
}
```

### 4.3 审计事件（独立资源）

```ts
interface AuditEvent {
  id: string;
  scope: 'customer' | 'order' | 'role' | 'system';
  scopeId: string;                       // customerId / orderId / roleId
  at: ISODateTime;
  by: Email | 'system';
  kind: string;                          // 见 §1.7
  text: string;                          // 人类可读摘要
  meta?: Record<string, unknown>;        // 结构化扩展
}
```

### 4.4 通知事件（推送给通知中心 / Webhook）

```ts
interface NotificationEvent {
  id: string;                            // 幂等键
  topic:                                 // 见 §3.1
    | 'customer.registered'
    | 'customer.suspended'
    | 'contract.added' | 'contract.terminated'
    | 'operator.invited' | 'operator.locked' | 'operator.mfa_reset'
    | 'data.revealed'
    | 'order.invoiced' | 'order.paid' | 'order.shipped' | 'order.delivered'
    | 'device.activated';
  occurredAt: ISODateTime;
  actor: Email | 'system';
  payload: Record<string, unknown>;      // 结构按 topic 不同
  audience: {                            // 通知中心负责实际派发
    customerId?: string;
    roleIds?: string[];                  // 例：含 data.reveal 的角色
    emails?: Email[];                    // 显式收件人
    channels: Array<'inapp' | 'email' | 'webhook'>;
  };
}
```

## 5. 给到下游项目的最小信息清单
做通知中心 / 客户门户 / 履约对接时，**至少需要本系统提供**：
1. § 1 全套枚举值（合同类型、订单状态、权限 ID、事件 kind）。
2. § 3.1 完整的事件清单及收件人规则。
3. § 4.4 `NotificationEvent` schema 与示例载荷。
4. Webhook 鉴权方式（建议 HMAC + 时间戳）与重试/幂等策略（建议至少送达 + `event.id` 幂等键）。
5. 脱敏字段清单与"是否需要 reveal 权限"。
